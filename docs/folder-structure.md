## 1. `/` — Repository Root

| File / Folder | Purpose |
|---------------|---------|
| `package.json` | **Source of truth** for project name, version, scripts, and dependency list. |
| `package-lock.json` | Deterministic dependency lock. Committed — do not delete. |
| `tsconfig.json` | TypeScript config (strict, path alias `@/*` → `src/*`). |
| `next.config.ts` | Next.js runtime config: security headers, image formats, package import optimization. |
| `postcss.config.mjs` | PostCSS pipeline → Tailwind v4 plugin. Edit only if adding plugins (autoprefixer is built-into v4). |
| `eslint.config.mjs` | ESLint 9 flat config with Next.js TS + Core Web Vitals presets. |
| `.env.example` | **Documented** template for env vars. Copy → `.env.local` for local development. |
| `.gitignore` | Comprehensive ignore list. Keep it in sync with new secret/config file conventions. |
| `LICENSE` | MIT — keep date + copyright holder up to date. |
| `README.md` | Public face of the project: badges, overview, quickstart, roadmap, FAQ. |
| `CHANGELOG.md` | Keep-a-Changelog formatted human-readable history of every tagged release. |
| `CONTRIBUTING.md` | Full contributor workflow: branch names, commit format, PR template, review rules. |
| `CODE_OF_CONDUCT.md` | Contributor Covenant 2.1 — what counts as harassment & enforcement ladder. |
| `SECURITY.md` | Vulnerability disclosure process, supported versions, in-scope/out-of-scope list. |
| `AGENTS.md` | Internal file with agent-specific rules and Next.js disclaimers. Leave as-is. |
| `.next/` | **IGNORED** · Build output generated by `next dev` / `next build`. Do not commit. Delete to clean. |
| `node_modules/` | **IGNORED** · Installed dependencies. |

**What NOT to put in root:**
- Random markdown files → put them in `docs/`.
- One-off scripts → `scripts/` folder if you add one.
- Test files → colocate them or use `__tests__/` inside the relevant `src/` folder.

## 2. `.github/` — GitHub Automation

```
.github/
├── ISSUE_TEMPLATE/
│   ├── config.yml              # Disables blank issues; sets contact links
│   ├── bug_report.md           # 🐛 Template: reproducibility checklist
│   ├── feature_request.md      # ✨ Template: problem → solution → alternatives
│   ├── documentation.md        # 📚 Template: which doc is broken
│   └── question.md             # ❓ Template: support request
├── PULL_REQUEST_TEMPLATE.md    # Checklist every PR author fills in
├── dependabot.yml              # Weekly dep updates (grouped by theme)
└── workflows/
    └── ci.yml                  # lint + typecheck + build on push/PR to main
```

### Naming

- `ISSUE_TEMPLATE/*.md` — kebab-case-named, prefixed with emoji-verb in frontmatter title.
- Workflow names: `<noun>.yml` with a `name:` field that starts with an emoji for the Actions UI.

### What belongs

Only GitHub-specific tooling. CI config is GitHub Actions; if moving to another CI provider, put that file at repo root or `.circleci/`, `.gitlab-ci.yml`, etc.

### What does NOT belong

- General scripts → `scripts/` (create if needed).
- DB SQL → `supabase/migrations/`.

## 5. `src/app/` — Next.js App Router (ROUTES)

> ⚠️ File names inside `app/` are **reserved names** by Next.js. Misnaming a file silently breaks routing!

### Reserved special filenames

| Name | Loads | Purpose |
|------|-------|---------|
| `layout.tsx` | Every page in this segment + children | Wrapper. Use for Navbar, Footer, shared context providers, global fonts. |
| `page.tsx` | Route match | The page itself. **Default export only** (required). |
| `loading.tsx` | Parallel to page | Suspense fallback shown while page / data is loading. |
| `error.tsx` | Parallel to page | Error boundary UI if page throws (must be CC `"use client"`). |
| `not-found.tsx` | Fallback or via `notFound()` | Custom 404 for this segment + children. |
| `route.ts` | API request | Route Handler (GET/POST/etc.) — no React UI here. |
| `sitemap.ts` | `/sitemap.xml` | MetadataRoute.Sitemap generator. |
| `robots.ts` | `/robots.txt` | MetadataRoute.Robots generator. |
| `favicon.ico` | `/favicon.ico` | Icon. |
| `opengraph-image.(png\|jpg\|tsx)` | `/opengraph-image` | Dynamic or static OG image generation. |

### Route segments (sub-folders of `app/`)

```
app/
├── about/
│   └── page.tsx                 /about          — Bio, skills, education, resume CTA
├── categories/
│   ├── page.tsx                 /categories     — All categories as cards
│   └── [slug]/
│       └── page.tsx             /categories/:slug — Projects filtered by category
├── certificates/
│   └── page.tsx                 /certificates   — Credential gallery grid
├── contact/
│   └── page.tsx                 /contact        — Contact form + info card
├── experience/
│   └── page.tsx                 /experience     — Timeline + education + skills
├── projects/
│   ├── page.tsx                 /projects       — All projects grid + search/filter
│   └── [slug]/
│       └── page.tsx             /projects/:slug — Single project detail page
├── services/
│   └── page.tsx                 /services       — Offerings cards + pricing/features
├── videos/
│   └── page.tsx                 /videos         — Embedded video showcase grid
├── favicon.ico
├── globals.css                  ← Tailwind entry + design tokens (single source of truth)
├── layout.tsx                   ← Root: html, body, fonts, Nav/Foot, Analytics
├── not-found.tsx                ← Site-wide 404
├── page.tsx                     /                — Home: Hero, Stats, Featured, CTA
├── robots.ts
└── sitemap.ts
```

### App folder — naming rules

| Rule | Example |
|------|---------|
| **Dynamic segments**: wrap param name in brackets `[param]` | `app/projects/[slug]/page.tsx` |
| **Catch-all**: `[...slug]`, optional catch-all `[[...slug]]` | `app/docs/[...slug]/page.tsx` (if we add docs routes) |
| **Never** name a subfolder the same as a reserved file | No `public/`, no `layout/` subfolder in app/ |
| Route folders are **lower-kebab-case** or **slug** | `categories`, `case-studies`, NOT `CaseStudies` |
| Components inside app/ route folders? | Keep UI in `components/` folder, NOT inside `app/`. App/ should contain only route-defining special files + their colocated data. |

**Why this separation?** It keeps the file-tree-as-routes table of contents clean. A new engineer can open `src/app` and instantly read every public URL in the product, without scrolling through 50 components.

### Components — Golden Rules

1. **Feature folders** (`home/`, `contact/`, `services/`…): Components that only ever appear inside one feature.
2. **Shared folder** (`shared/`): Used across **two or more** feature folders.
3. **UI folder** (`ui/`): Primitives — no domain data, no feature vocabulary. Button, Card, Input, Badge. Wraps Radix.
4. **Layout folder** (`layout/`): Nav, foot, scroll wrappers — used by `app/layout.tsx`.
5. **Providers folder**: Tree-wide context providers (theme, analytics, Supabase session).

### Naming Convention (CRITICAL — be consistent)

| Kind | Case | Example |
|------|------|---------|
| **Component file names** | kebab-case `.tsx` | `project-card.tsx`, not `ProjectCard.tsx` |
| **Component function** | PascalCase export | `export function ProjectCard() {…}` |
| **Component folder names** | kebab-case | `contact-form/` not `ContactForm/` |
| **Props interface** | `<ComponentName>Props` | `interface ProjectCardProps {…}` |
| **Variants (CVA)** | `<rootName>Variants` | `const buttonVariants = cva(…)` |
| **Hooks** | `use-thing.ts` export `useThing` | `use-scroll-position.ts` |
| **Utils** | `do-the-thing.ts` | `format-date.ts`, `slugify.ts` |

**Why kebab-case filenames for components?** Four reasons:
1. Git handles case-insensitive filesystems (macOS/Windows) without collisions.
2. They read naturally in imports: `import { ProjectCard } from "@/components/shared/project-card"`.
3. Consistency with Next.js reserved filenames.
4. Matches how the feature folders are named (`home/hero.tsx` is consistent).

## 7. `src/data/` — Typed Data Collections

> One module per collection. Type interface first, then the array, then helper queries.

```
data/
├── categories.ts          Category[] + getCategoryBySlug()
├── certificates.ts        Certificate[]
├── experience.ts          Experience[], Education[], Skill[], stats[]
├── projects.ts            Project[] + getProjectBySlug(), getFeaturedProjects(), getProjectsByCategory()
├── services.ts            Service[] + CURRENCY_RATES{}
└── videos.ts              Video[]
```

### Data file pattern (every file follows this)

```ts
// 1. Interface — always exported
export interface Project { slug: string; title: string; … }

// 2. Collection
export const projects: Project[] = [ … ];

// 3. Helpers — tiny pure functions that filter/query the collection
export function getProjectBySlug(slug: string) { return projects.find(…) }
export function getFeaturedProjects() { return projects.filter(…) }
```

**Do NOT** put React logic here. No hooks, no components, no `useState`. Pure TypeScript only.

This folder is the bridge between "hardcoded content for v1" → "Supabase CMS for v2". In v2 the helper functions will swap to `supabase.from('projects').select(…)` and callers won't need to change.

## 8. `src/lib/` — Utilities & SDK Wrappers

> Non-React code. Pure helpers, typed SDK factories, constants.

```
lib/
├── animations.ts            Framer Motion variant presets (fadeInUp, blurReveal, stagger…)
├── constants.ts             SITE_CONFIG + NAV_LINKS — single source of branding truth
├── utils.ts                 cn(), formatDate(), formatCurrency()
└── supabase/
    ├── client.ts            createClient() — "@supabase/ssr" for "use client" files
    └── server.ts            createClient() — async cookie-wrapped for Server Components / Route Handlers
```

### Rules for `lib/`

- No React hooks allowed. If a file imports from `"react"`, it belongs under `components/` (or a future `hooks/` folder).
- One well-understood helper per export. Avoid kitchen-sink files.
- Environment-dependent code (anything that reads `process.env`) belongs in `lib/supabase/*` or a similar clearly-named file. Do NOT scatter `process.env` reads across the app.
- When adding a new category of util, create a new subfolder: `lib/email/`, `lib/validation/`, etc.

## 9. Future Folders (Roadmap)

These are **not present in v1.0.0**. Don't add them until you need them.

| Folder | Purpose | When to add |
|--------|---------|-------------|
| `src/hooks/` | Shared React hooks: `use-scroll-position`, `use-debounce`, `use-media-query` | When ≥ 2 files need the same hook. |
| `src/types/` | Shared global types: `api.d.ts`, database-generated types | When types are shared across 3+ modules and aren't co-located cleanly. |
| `src/app/api/` | Route handlers: `/api/contact`, `/api/revalidate`, `/api/upload` | When adding server write paths. |
| `src/middleware.ts` | Edge middleware | When adding RLS-gated /admin routes or Geo-redirects. |
| `src/styles/` | Additional CSS modules or theme files | **Don't add.** Everything should be Tailwind / globals.css tokens. |
| `scripts/` | Standalone Node scripts (seed-db, sync-stripe, etc.) | When you need non-build scripts. |
| `supabase/migrations/` | `migrations/*.sql`, `seed.sql` | When moving data from `src/data/` TS to Supabase tables. |
| `__tests__/` | `vitest` or `jest` unit tests | When adding test infra. |

## 10. Decision Record — Why This Structure?

1. **Next.js App Router convention first.** Do not fight the framework. `app/` = routes, period.
2. **Screaming Architecture.** Open `src/` and you immediately see three loud buckets: `app` (what it does), `components` (how it looks), `data` (what content it has), `lib` (how it wires).
3. **Colocation by feature over by type.** Home's Hero is in `components/home/hero.tsx` not `components/Hero.tsx`. When you delete a page, deleting its folder is a single action.
4. **Single sources of truth.** Branding → `lib/constants.ts`. Colors → `app/globals.css` tokens. Routes → `app/` tree. Data → `data/` collections. No duplication. No syncing.
5. **Flat is better than nested.** 2–3 levels max. If a folder has one file, it's still a folder because it reserves room for variants later (`home/hero.tsx` can grow `home/hero-particles.tsx`).
6. **Senior engineer onboarding time.** Goal: new hire can make a "change the footer links" commit in < 10 minutes. They open `lib/constants.ts` (NAV_LINKS) → done. "Add a new project?" → `data/projects.ts` → done.
